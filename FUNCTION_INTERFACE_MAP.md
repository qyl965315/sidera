## Interface / duplication decisions

1. Human intent and config validation formerly lived in the CLI; they are now shared Core operations. There is one implementation for each, with browser and file transports.
2. CLI and UI safe stop now reuse the same exact-owner lifecycle client. The pipe and child IPC are retained because they authenticate the owner and check open external turns.
3. UI live read defaults no longer reference another development checkout. Static launcher and Vite use one canonical frontend projection.
4. Existing MCP wrappers mostly forward transport data, but their protocol schema, principal binding and exposure catalog are independent responsibilities. Removing the gateway just to shorten the chain would weaken authentication and northbound contract stability.
5. Legacy native config mapping remains tested compatibility; production UI fallback remains ineligible. Hard-coded diagnostic scripts are not in the ordinary startup path.
6. Missing ordinary flows are not hidden: additional Host adapters, private credential installation, frontend transport configuration, Node retirement and active Session handoff still require a bounded product-specific Human workflow. The current UI never exposes a generic shell, arbitrary file path or arbitrary RPC method to fill those gaps.

## API inventory / security

GET `/api/setup/status`, GET `/api/r1/snapshot`; POST `/api/setup/human`, `config`, `node`, `profile-review`, `chief-review`, `reconcile-review`, `confirm`, `provision`, `intent`, `core-start`, `core-stop`.

All are bound to 127.0.0.1; Host must match the exact local origin; mutations require exact Origin and JSON; cross-site Fetch Metadata is rejected; objects reject unknown fields; inputs have bounded size. Errors use stable codes. No Node RPC or MCP registration references LocalSetup, admission review IDs or confirmation operations. A model with a Node credential cannot switch to a Human principal. A local process with full OS/browser control is inside the local operator trust boundary; same-origin is not cryptographic evidence that a physical person clicked.
